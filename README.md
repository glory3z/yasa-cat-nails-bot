# yasa-cat-nails-bot
Telegram mini-app для онлайн-записи на маникюр (Yasa cat)

## Напоминания о визите

По умолчанию клиент получает уведомления за **24 часа** и за **2 часа** до подтверждённой записи. В сообщении — услуга, дата, местное время, мастер, адрес и кнопка открытия записи.

Для существующего бота выполните в SQL Editor его проекта Supabase два файла по порядку:

1. `database/reminders.sql` — очередь и обработка подтверждений, отмен и переносов.
2. `database/reminders-cron.sql` — один вызов `/internal/reminders` каждую минуту через Supabase Cron/pg_net.

Для новой копии сначала выполните `database/schema.sql`, если он есть, затем эти два файла. У каждого бота должен быть собственный проект базы. Повторный запуск установщиков не создаёт дополнительных таймеров. Настройки адреса сервиса и ключа запроса приложение регистрирует автоматически при старте из своих `APP_URL`, `BOT_TOKEN` и `WEBHOOK_SECRET`. Дополнительные ключи вручную передавать не нужно. Планировщик хранит только производный ключ отдельного служебного маршрута в закрытой схеме, не токен Telegram. Каждый вызов подписывается и получает одноразовый идентификатор; повторное использование запроса отклоняется. Сам ключ в журнал HTTP-запросов не передаётся.

Переменные окружения:

- `REMINDERS_ENABLED=true` — включение напоминаний; `false` отключает их после перезапуска.
- `REMINDER_OFFSETS_HOURS=24,2` — от одного до пяти разных целых интервалов в часах, максимум 168 часов.

После изменения настроек нужен деплой/перезапуск. `/health` показывает `reminders: configured` после регистрации адреса. Это подтверждает регистрацию приложения, а работу таймера можно проверить в Supabase Cron. Авторизованным администраторам доступен `GET /api/admin/reminders`: состояние и количество ожидающих, отправленных и проблемных уведомлений без ключей.

Уведомления создаются только для подтверждённых будущих записей. Если на момент подтверждения интервал уже прошёл, такой старый сигнал не создаётся. Отмена и запрос переноса убирают ожидающие напоминания; после подтверждения нового времени создаются новые. Отправленные уведомления сохраняются в истории и не отправляются повторно для той же даты записи и интервала. Уведомление, уже переданное Telegram одновременно с отменой, отозвать автоматически нельзя.

Очередь общая для всех процессов приложения и сохраняется после перезапуска. Отправка может немного задержаться из-за пробуждения сервера или сети. Пропущенные более чем на 20 минут напоминания не отправляются пачкой после долгого простоя; напоминания о прошедшем визите не отправляются.

Если Telegram явно отклонил запрос из-за лимита, повтор выполняется через `retry_after`. При блокировке бота клиентом повторы прекращаются. Если соединение оборвалось после начала отправки, результат может быть неизвестен: запись получает `uncertain` и автоматически не повторяется, чтобы не прислать дубль. Telegram `sendMessage` не предоставляет гарантии «ровно один раз» при сетевых обрывах.

Тесты очереди, отмен и переносов выполняются локально без сообщений клиентам. Для проверки фактической доставки используйте отдельную тестовую запись с разрешения владельца Telegram-аккаунта; рабочие записи ради теста менять не нужно.
